基于大语言模型的智能化毕业设计辅助系统设计与实现

5. 后续如何收尾，遇到的问题如何解决。

## 第 2 页：研究背景与问题

标题：研究背景：从流程管理到智能辅助

要点：

- 传统毕业设计系统偏重课题发布、申报审核、材料提交等流程记录。
- 学生在课题理解、文献阅读、技术问题定位和阶段规划中仍依赖线下指导。
- 大语言模型具备自然语言理解、问答和摘要能力，适合补充毕业设计过程支持。
- 本课题目标不是再做一个普通管理后台，而是构建“流程管理 + AI 辅助”的工作台。

讲述备注：

毕业设计周期较长，涉及选题、资料检索、开发实现和论文撰写。传统系统能够记录流程，但对学生真实研究过程的帮助有限。因此本课题希望把大语言模型能力引入到具体毕业设计场景中。

## 第 3 页：毕设研究内容

标题：研究内容：AI 学术助手工作台

要点：

- 身份与学期：提供用户身份、角色和当前学期上下文。
- 选题与志愿：支持课题浏览、详情查看、志愿申报和最终指派。
- 智能聊天：围绕课题理解、技术方案、论文结构提供异步 AI 问答。
- 文档处理：支持 PDF 上传、解析、摘要和要点提取。
- 任务看板：跟踪开题、实现、论文、答辩准备等阶段任务。

讲述备注：

系统把毕业设计中的关键行为组织为一个工作台。它既保留传统系统的选题和过程管理能力，也增加了聊天问答和文档摘要两条 AI 辅助主线。

## 第 4 页：技术要求与技术路线

标题：技术要求：可运行、可维护、可演示

要点：

- 后端采用 Flask，强调接口契约、分层架构和异步任务。
- 前端采用 React、Vite、TypeScript、React Router、Tailwind CSS。
- 数据请求使用 Axios 与 TanStack Query，登录态使用 Zustand 管理。
- AI 相关耗时任务采用 pending / running / done / failed 状态流。
- 前后端通过 spec/contract.yaml 约束接口结构与错误格式 ErrorEnvelope。

讲述备注：

技术选型重点不是堆叠框架，而是保证系统能稳定表达 AI 场景。聊天和文档处理都可能耗时，所以必须通过异步状态流来组织，而不是同步阻塞接口。

## 第 5 页：总体架构设计

标题：总体架构：前后端分离 + 异步任务层

要点：

- 前端工作台：登录、首页、聊天、文档、选题、任务看板。
- API 层：负责鉴权、参数校验、请求受理和结果返回。
- Service / Use Case 层：负责事务边界、业务编排、消息组装、文档分块。
- Task / Worker 层：消费队列任务，执行模型调用和文档处理。
- Adapter 层：封装大模型、PDF 解析等外部能力。

讲述备注：

架构上我把 Web 请求和 AI 执行解耦。API 只负责受理和查询，真正耗时的模型调用由 Worker 完成，这样前端可以展示任务过程，后端也更容易处理失败和重试。

## 第 6 页：异步任务机制

标题：核心机制：状态驱动的异步 AI 任务

要点：

- 用户发起聊天或上传 PDF 后，接口先创建任务并返回任务标识。
- Worker 将任务状态从 pending 更新为 running。
- 任务完成后进入 done，并回写消息内容或文档摘要结果。
- 任务失败后进入 failed，并返回结构化错误信息。
- 前端根据任务状态轮询，到 done / failed 后自动停止。

讲述备注：

这是本课题比较重要的技术点。AI 调用和 PDF 处理都不是瞬时操作，使用异步任务可以提升响应速度，也能把处理过程可视化出来。

# 前端整体修改总览

## 现状判断

当前 `frontend/` 已经完成独立工程初始化、应用壳、登录链路、`/app/dashboard`、`/app/chat`、`/app/documents`、`/app/topics`、`/app/taskboard` 的基础实现。

其中，`/app/topics` 已进一步补上“老师分析 + 学生推荐”的前端演示闭环，页面入口见 [topics-page.tsx](/d:/毕业设计/frontend/src/pages/topics/topics-page.tsx)。

## 已完成内容

- 独立前端工程已落在 `frontend/`
- 路由已覆盖 `/login` 和全部 `/app/*` 页面
- 应用壳已具备左侧导航、顶部栏、主内容区
- Chat、Documents、Topics 已接入真实后端链路或真实列表详情链路
- Topics 已新增前端侧的题目分析与推荐试算
- 已补齐基本测试与构建验证

## 仍建议修改

### P0

- 将 Topics 的“老师分析”和“学生推荐”从前端演示逻辑升级为真实后端接口调用
- 若产品表达更清晰，建议把 Topics 拆成“老师端分析页”和“学生端推荐页”
- 为新的推荐/分析链路补充 `ErrorEnvelope`、loading、empty state 和 retry 体验
- 补充 route 级 `errorElement`，避免页面异常时直接暴露 React 错误页

### P1

- 接入 `Taskboard` 真实数据与状态流转
- 补齐 `Dashboard` 的真实统计聚合
- 统一页面空状态、骨架屏和错误页风格
- 清理开发环境代理与联调配置
- 补充更明确的教师端 / 学生端产品文案

### 论文与契约层

- 若要让“老师输入题目后调用大模型分析、学生输入画像后推荐”成为完整论文逻辑，建议在后端契约中补分析接口或明确推荐接口字段
- 建议在 `spec/contract.yaml` 中补充或细化题目分析结果、学生画像输入、推荐解释字段
- 建议把“大模型负责分析与解释、规则负责约束与排序、人工负责确认”写进论文实现说明

## 当前最推荐的下一步

1. 把 Topics 的分析/推荐从本地演示逻辑切换成真实后端接口
2. 接入 Taskboard 真实接口
3. 补 Dashboard 真实统计
4. 再统一整理答辩文档和接口映射

## 结论

如果以“毕业设计可答辩、可讲清逻辑”为标准，当前前端已经可用，但仍建议继续补齐 Topics 的真实分析/推荐链路和 Taskboard 真实数据，这两项最能增强论文完整性与产品闭环。

# 毕业设计答辩说明稿

## 3 分钟答辩说明稿

各位老师好，我的毕业设计题目是“基于大语言模型的智能化毕业设计辅助系统设计与实现”。

我选择这个题目的原因，主要是因为传统毕业设计系统虽然能够支持课题发布、学生申报和过程材料提交，但整体上更偏向流程记录，对学生在课题理解、文献阅读、问题求解和任务推进这些关键环节的帮助比较有限。尤其是在毕业设计周期较长、教师指导精力有限的情况下，学生经常会在选题理解不充分、资料消化困难和阶段任务不清晰这几个方面遇到明显问题。

基于这个背景，我的课题不是单纯再做一个教务管理后台，而是希望把大语言模型的文本理解和问答能力，引入到毕业设计场景中，做一套“管理流程 + 智能辅助”结合的系统。

在系统设计上，我把整体能力分成几个部分。第一部分是基础业务能力，包括身份认证、学期管理、课题管理、志愿填报和任务看板。第二部分是智能辅助能力，主要包括智能聊天和 PDF 文档摘要。第三部分是系统稳定性相关能力，也就是我这次实现中比较重视的异步任务机制。

这个项目的一个重点，不是“能不能调通大模型接口”，而是“怎样把大模型合理地放进业务系统里”。所以我在后端设计中专门做了分层和异步化处理。API 层只负责请求受理、参数校验和状态返回；Service 层负责事务和入队；Use Cases 层负责聊天消息组装、文档分块和关键词抽取这类编排逻辑；真正调用大模型的部分，统一放在队列和 Worker 进程里异步执行，而不是在 Web 请求线程里同步等待结果。

这样设计有三个好处。第一，接口响应会更快，聊天和文档上传都可以先返回任务状态，不会因为模型耗时导致页面长时间等待。第二，任务状态可以统一管理，比如 pending、running、done、failed，便于前端展示，也便于出错后排查。第三，业务逻辑边界更清晰，后续扩展和测试都更方便。

从当前完成情况来看，我已经完成了项目后端核心能力的设计与实现基础，也形成了比较完整的接口契约、架构规格和任务执行文档。前端部分，我没有继续沿用开题阶段原本设想的 Vue 方案，而是重新规划为独立的 React + Vite + TypeScript 项目，定位为“AI 学术助手工作台”，并已经完成正式设计文档。这样调整的原因，是希望前端更贴合答辩演示主线，重点展示登录、工作台首页、智能聊天、文档任务、选题和任务看板这几条链路。

总体来说，这个课题的价值不只是增加了 AI 问答功能，而是尝试把毕业设计系统从单纯的流程平台，扩展为一个能够提供过程支持和智能辅助的工作台。后续如果继续完善，我会优先完成前端落地和真实联调，并进一步增强文档分析和选题辅助能力。

我的汇报完毕，谢谢各位老师。

## 5 分钟扩展说明稿

各位老师好，我的毕业设计题目是“基于大语言模型的智能化毕业设计辅助系统设计与实现”。

本课题关注的问题，来源于毕业设计过程中的两个现实矛盾。第一个矛盾是，传统系统更擅长做流程管理，但不擅长做学习支持。它可以记录课题、学生志愿和文档提交状态，却很难帮助学生理解课题、阅读文献或者解决开发中的具体问题。第二个矛盾是，大语言模型虽然具备较强的自然语言理解和文本生成能力，但如果直接把它以同步接口方式接到 Web 系统里，往往会带来响应慢、错误恢复困难和系统不稳定的问题。

因此，这个课题的核心目标，是做一套既能覆盖毕业设计基础业务，又能合理接入大语言模型能力的智能辅助系统。

我在系统中主要设计了六类能力。第一类是身份认证和学期管理，用来建立统一的用户和学期上下文。第二类是课题管理与双向选择，包括课题发布、学生申报、教师确认以及最终指派关系维护。第三类是智能聊天，学生可以围绕课题理解、技术方案、代码问题和论文结构发起提问。第四类是文档上传与摘要辅助，学生上传 PDF 文献后，系统可以异步完成解析和总结。第五类是任务看板，用于展示毕业设计过程中的阶段任务和里程碑。第六类是推荐与辅助展示能力，用于提供一定的结构化浏览和筛选支持。

在技术实现上，我将系统重点分成五层。最上层是 API 层，负责请求入口和返回结果。第二层是 Service 层，负责事务、业务入口和任务入队。第三层是 Use Cases 层，负责复杂编排逻辑，例如聊天消息如何组装、历史上下文如何裁剪、PDF 文档如何分块。第四层是 Task 层，也就是异步任务层，负责从队列消费任务、执行处理并回写状态。第五层是 Adapter 层，负责调用大模型、PDF 解析等外部能力。

这套分层设计里，最关键的一点是，我没有把大模型调用放在 API 层同步执行，而是统一走“受理请求、创建任务、异步执行、轮询状态”这条链路。比如在聊天场景里，系统会先创建用户消息和 assistant 占位消息，接口先返回受理成功和任务标识；之后由 Worker 进程异步调用模型，再把生成结果回写到消息记录中。文档处理也采用类似思路，先做 PDF 解析，再做分块总结，整个过程都通过任务状态进行追踪。

这样做的意义主要有三点。第一，提升接口响应性，避免用户长时间等待。第二，提升可维护性，错误处理、重试和状态更新都有统一位置。第三，提升演示效果，因为答辩时可以清楚展示系统不仅能“出结果”，还能“展示过程”。

从当前成果来看，我已经完成了项目后端核心能力、接口契约和架构规格方面的工作，并围绕聊天、文档、选题和志愿等主要业务建立了较完整的后端主线。前端部分，为了更贴合答辩展示和产品化演示，我没有继续使用开题阶段的 Vue 设想，而是重新设计为独立的 React + Vite + TypeScript 项目，并已经形成正式设计文档。这样做并不是偏离课题，而是根据项目实际推进情况，对“展示效果、工程可控性和答辩主线”进行了更合理的技术调整。

如果老师问这个项目的创新点，我会总结为三点。第一，不是单纯把大模型嵌进页面，而是把它工程化地纳入毕业设计业务系统。第二，不只关注选题流程，而是把选题、文档、问答和过程管理统一到同一场景里。第三，通过异步任务和清晰分层，提升了系统的稳定性和扩展能力。

如果继续完善，下一步我会优先完成独立前端项目开发，形成更完整的产品化演示，同时进一步强化文档处理结果展示和任务看板体验。

我的汇报完毕，谢谢各位老师。

## 老师追问时的补充口径

### 1. 为什么和开题报告里的前端技术不一样

开题阶段我最初按常见教学管理系统思路，写的是 Vue 3 方案。但在实际推进过程中，我把系统展示重点从“普通管理后台”调整为“AI 学术助手工作台”，同时结合当前仓库实际结构，决定采用独立的 React + Vite + TypeScript 前端项目。这个调整不影响课题目标，反而让前后端分离更清晰，也更适合答辩演示主线。

### 2. 现在到底完成到了什么程度

目前后端核心能力、接口契约、架构规格和异步任务主线已经完成；前端方面已经完成正式设计方案，但产品化界面还在待实现阶段。因此我会如实表述为“后端核心原型已完成，前端已完成正式设计并可继续落地”，不会夸大成全部上线。

### 3. 你的创新点是什么

我的创新点不在训练新模型，而在于把大语言模型能力和毕业设计业务流程结合起来，并且通过队列、Worker、分层约束和统一任务状态，把 AI 能力做成一个可落地、可维护的系统能力。

### 4. 为什么一定要做异步任务

因为大模型调用和文档处理都属于高耗时操作。如果直接在接口线程里同步执行，系统响应会很慢，也不利于错误恢复。采用异步任务后，接口可以快速返回，任务过程可追踪，系统稳定性更高。

### 5. 这个系统最适合展示哪几个功能

最适合展示的是四条主线：登录进入工作台、发起智能聊天、上传 PDF 获取摘要结果、查看选题和任务看板。这几条链路能同时体现业务完整性和 AI 辅助能力。
